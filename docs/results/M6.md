# M6 results: soak test

## Four hours of the live show (2026-10-17)

`app\build\windows-msvc\release\psyight_soak.exe data\OculusDrift.mp3 --minutes 240`: live mode as the app runs it, on the file capture source (the track looping at real-time pace, silent). Capture, the analysis thread with the M4 student, and the show thread rendering the default rig at 60 fps through the limiters and the virtual node, with no network. The machine was busy for much of the run: Demucs separation and student training on the GPU and CPU, builds, and GUI tests.

| Measure | Result |
|---|---|
| Frames | 862,864 in 14,400 s: 59.92 fps |
| Late frames (a tick more than a frame late) | 264, all in a few bursts: minutes 6 and 8 (81 and 73), 202 (48) and 215 (58), plus four single frames. They coincide with builds, GUI tests and the four-track live checks running alongside. No late frames in quiet minutes. |
| Render time (sampled each minute) | 0.12 to 0.40 ms per frame |
| Analysis delay | 13.2 to 15.5 ms throughout |
| Analysis thread load | about 11 to 20% of its 2 ms ticks, peak 64% under the parallel load |
| Dropped capture samples | 0 |
| Memory | working set 85.6 MB at the start, 82.6 MB at the end; private bytes 79.4 MB to 79.3 MB (no growth) |
| Beat loop | locked at 150.00 BPM in every sampled minute but one: minute 7, just after the looped track restarted (its intro has no kick, and the kick returns at a new phase, as at a track change). |

The show stage and the analysis hold up for four hours with no leak and no drift. Late frames appear only when other heavy work shares the machine. On a show laptop, close other software, as the operator guide says.

Not covered: the GUI thread (the soak has no window), real audio devices (loopback and interfaces drop out and change formats), and the network path to a node.
