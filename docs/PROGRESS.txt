## Gotchas learned the hard way
- **Windows Firewall and discovery:** a dismissed "Allow access?" prompt leaves inbound Block rules for psyight.exe (Domain and Public); a direct cable to the node is a Public network, so ArtPollReplies are dropped and discovery finds nothing while Python probes work. Also: a probe script bound to port 6454 gets no replies while Psyight runs (Psyight holds the port and takes them). Fixed on this machine (2026-10-23) with one Allow rule: inbound UDP, psyight.exe (the release build path), remote LocalSubnet. Preflight now says so when no node answers.
- **Scripted C++ edits:** write Python edit scripts with the Write tool and put C++ text in raw strings (r"""..."""): an escape such as '\0' otherwise lands in the source as a real NUL byte. Bash heredocs mangle backslashes too. Don't name a variable `small` (a macro in Windows headers).
- **The owner often has psyight.exe open.** Linking Release then fails (LNK1104). Build and test the Debug preset instead, and ask the owner to close the app before a Release build.
- **Never inject mouse or keyboard input unless Psyight is the foreground window.** An early test clicked into the owner's rekordbox. Guard every scripted input with `GetForegroundWindow() == psyight` and abort otherwise. For screenshots without focus use `PrintWindow(hwnd, hdc, 2)` (works for the GL window behind other windows).
- Test labelling on a **copy** of the track in a scratch folder, so autosave never writes into the owner's labels file.
- Running the app from the repo root rewrites the owner's `imgui.ini` (their panel layout). Back it up before GUI tests and restore it afterwards.
- VS Code's CMake Tools auto-reconfigures `app/build` when CMakeLists.txt is saved; concurrent CLI configures corrupt the cache. Wait a few seconds after editing CMakeLists.txt.
- Keep scratch builds at short paths (MAX_PATH: about 120-character prefixes break cl with C1083).
- PowerShell 5.1 mangles stdin piped to native tools; use the Bash tool (Git Bash) for that. `git credential fill` works from Bash.
- Scripted key input: GLFW maps keys by scancode. `keybd_event` with scancode 0 turns arrows and Delete into numpad keys, and the extended flag with scancode 0 gives an unknown key (one such run even left the app in a state where a later key deleted notes). Send the real scancode with the extended flag: Up 0x48, Down 0x50, Delete 0x53. Letters with Ctrl work with scancode 0. In PowerShell, don't name helpers Move, Drag or Click: `Move` is an alias of Move-Item and aliases win.
- Verify GUI tests through the saved labels file (Ctrl+S, then read the JSON), not only screenshots.
- Ask before taking focus for a scripted GUI test when the owner is in another app (they approved a ~20 s test on 2026-10-16).
- Bash heredocs or `python -c` with apostrophes or `\n` escapes break in this tool: write edit scripts to the scratchpad and run them with `python -I <file>`, and assert each replacement matched (two silent misses cost time here).
- `std::getenv` triggers C4996, an error under /WX. Don't hide build output with `Select-Object -Skip`: errors scrolled away and a stale binary ran.
- The C: drive is 96% full (about 35 GB free): stems take about 0.4 GB per 7-minute track.
- Demucs decodes MP3 differently from miniaudio: its stems ran 47 ms ahead on OculusDrift. Always align stems to the mix (analyse_track does).
- Low bass needs analysis windows of at least one period (24 ms at E1). Shorter ones see the waveform: per-hop energy and 1024-sample flux swing 30 dB within a period and fire false onsets.
- clang-format: `C:\Program Files\Microsoft Visual Studio\18\Community\VC\Tools\Llvm\x64\bin\clang-format.exe`. Run `-i`, then `--dry-run --Werror` on app/src and app/tests before committing.

## ONNX Runtime in the app (owner decided 2026-10-17: option 4, with option 2 CPU as the fallback)
Checked at the pinned vcpkg baseline b1b19307 (2025-08-30): the only runtime port is `onnxruntime-gpu` 1.19.2, which downloads Microsoft's CUDA release zip and is `ONLY_DYNAMIC_LIBRARY` (our triplet is static: it needs a per-port dynamic override). No CPU or DirectML port.
1. vcpkg onnxruntime-gpu: CUDA and cuDNN DLLs on every machine that runs the show; no DirectML. Poor fit.
2. Microsoft's prebuilt release (CPU zip, or the Microsoft.ML.OnnxRuntime.DirectML NuGet package) through a vcpkg overlay port in the repo: MIT, a few DLLs next to psyight.exe, CPU and DirectML. DirectML.dll's redistribution terms [Verify].
3. Build ONNX Runtime from source in an overlay port: full control, static possible, long builds and upkeep.
4. No runtime: the student is a small causal TCN (359k parameters), so hand-written streaming inference in C++ (each dilated layer keeps its past activations, one new frame per hop) costs about 0.7 MFLOP a hop, well under 0.1 ms on one core [Verify by measuring]. No dependency, bit-identical runs (the determinism rule), naturally causal for live mode; tied to this architecture, checked against onnxruntime's outputs in a test. ONNX stays the training export.
Done 2026-10-17: app/src/ml/student.* (see docs/results/M4.md "In the app"): matches onnxruntime within 2e-5, streaming and whole-track bit-identical, OculusDrift F 0.981 exactly as the Python path, 37 us a frame. GUI A/B in the bass roll (DSP or M4 student), scored by the Scoring tab. `psyight_eval <audio> --student`.
Decision: 4, with 2 (CPU) as the fallback if the model family changes. The weights stay in data/m4 (trained on private music, never committed); the parity test uses a randomly initialised student of the same shape, exported to ONNX with reference outputs from onnxruntime, which can be committed.

## Known issues
- Fixed (2026-10-17): render-time jitter. The transport publishes its position with a timestamp under a seqlock (position_now extrapolates between callbacks) and the show thread smooths it with a delay-locked loop (core/playhead_clock.h). At 60 fps on the null backend the frame-to-frame step went from 10 to 30 ms (sd 6.06 ms) to 15.9 to 17.7 ms (sd 0.34 ms): psyight_tests -tc="transport: render-time steps at 60 fps" --no-skip.
- Closing the app while a track is still loading waits up to about 3 s for the analysis (make it cancellable).
- Spectrogram display resolution at the low end is about half a bin (SPEC 6.1); CQT is an M2 option.
- Bass tracker v0 limits: gaps shorter than the 25 ms envelope window run to the next onset (a dip-depth estimate was tried and reverted: decay looks like a gap); long notes decaying below k x peak end before their gate; long notes held under a kick are split; notes under about two periods get a wrong pitch with low confidence.
