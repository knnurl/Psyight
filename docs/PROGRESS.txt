## Gotchas learned the hard way
- **The owner often has psyight.exe open.** Linking Release then fails (LNK1104). Build and test the Debug preset instead, and ask the owner to close the app before a Release build.
- **Never inject mouse or keyboard input unless Psyight is the foreground window.** An early test clicked into the owner's rekordbox. Guard every scripted input with `GetForegroundWindow() == psyight` and abort otherwise. For screenshots without focus use `PrintWindow(hwnd, hdc, 2)` (works for the GL window behind other windows).
- Test labelling on a **copy** of the track in a scratch folder, so autosave never writes into the owner's labels file.
- Running the app from the repo root rewrites the owner's `imgui.ini` (their panel layout). Back it up before GUI tests and restore it afterwards.
- VS Code's CMake Tools auto-reconfigures `app/build` when CMakeLists.txt is saved; concurrent CLI configures corrupt the cache. Wait a few seconds after editing CMakeLists.txt.
- Keep scratch builds at short paths (MAX_PATH: about 120-character prefixes break cl with C1083).
- PowerShell 5.1 mangles stdin piped to native tools; use the Bash tool (Git Bash) for that. `git credential fill` works from Bash.
- Scripted key input: GLFW maps keys by scancode. `keybd_event` with scancode 0 turns arrows and Delete into numpad keys, and the extended flag with scancode 0 gives an unknown key (one such run even left the app in a state where a later key deleted notes). Send the real scancode with the extended flag: Up 0x48, Down 0x50, Delete 0x53. Letters with Ctrl work with scancode 0. In PowerShell, don't name helpers Move, Drag or Click: `Move` is an alias of Move-Item and aliases win.
- Verify GUI tests through the saved labels file (Ctrl+S, then read the JSON), not only screenshots.
- Ask before taking focus for a scripted GUI test when the owner is in another app (they approved a ~20 s test on 2026-10-16).
- Bash heredocs or `python -c` with apostrophes or `\n` escapes break in this tool: write edit scripts to the scratchpad and run them with `python -I <file>`, and assert each replacement matched (two silent misses cost time here).
- `std::getenv` triggers C4996, an error under /WX. Don't hide build output with `Select-Object -Skip`: errors scrolled away and a stale binary ran.
- Low bass needs analysis windows of at least one period (24 ms at E1). Shorter ones see the waveform: per-hop energy and 1024-sample flux swing 30 dB within a period and fire false onsets.
- clang-format: `C:\Program Files\Microsoft Visual Studio\18\Community\VC\Tools\Llvm\x64\bin\clang-format.exe`. Run `-i`, then `--dry-run --Werror` on app/src and app/tests before committing.

## Done so far (M1)
- Build: presets, vcpkg, /W4 /WX clean, clean-clone verified. GL 3.3 core window, docking ImGui, ImPlot; GUI paced with `DwmFlush` (8% of a core instead of 104%).
- Core: `Result<T>`, timebase and manual `Grid` (snap, slot in bar, grid lines), SPSC queue, parameter registry with presets.
- Audio: decode WAV/FLAC/MP3 to 48 kHz stereo (FLAC untested; owner says not needed now), WASAPI transport (play, pause, seek, loop, volume), half-speed pitch-preserving audition (Signalsmith Stretch 1.4.0 + Linear 0.6.4, MIT, vendored in `app/third_party`, 90 ms latency compensated).
- Analysis front end (file mode, deterministic, parallel): STFT, log spectrogram, filterbank energies and envelopes, spectral flux, and **bass pitch salience** (harmonic sum of 8 harmonics on semitone rows A0 to E4, own 8192-sample STFT). 398 s track in 2.6 s.
- Labels: SPEC 6.10 file, atomic save, strict parsing; `LabelEditor` with undo/redo and gestures; autosave every 60 s, on track change and exit; an unreadable labels file is never overwritten.
- Scoring (no panel yet): onset P/R/F with maximum, closest-pairing matching; offset errors and the mir_eval offset rule; pitch within 50 cents with octave errors; gate-ratio MAE; per complete region with edge-aware matching. Matches mir_eval 0.8.2 on 3576 cases.
- Synthetic generator (SPEC 6.11) with exact labels, six patterns, slides, ducking, hats, noise; checked by mutation testing.
- GUI: transport panel; analysis view (spectrogram, band energy, flux; click to seek; loop shown; follow playhead, pan, zoom); bass roll (pitch background, create/move/resize/delete, snap with Alt for free, Ctrl+click seek, middle-drag pan, middle double-click fit); note inspector (all fields, typed pitch F1/29, regions); default layout v2 with View > Reset layout.
- Multi-note editing in the bass roll: drag a box on empty space (Shift adds), Shift+click toggles, Ctrl+A selects the notes in view, Escape clears. Drag, Up/Down (Shift: octave) and Delete act on the whole selection. Ctrl+C, Ctrl+V (at the mouse, else the playhead), Ctrl+D or Duplicate with "Repeat every" (Auto, 1/16 to 4 bars) and a count, and "Fill to region end". Rules in `src/io/note_pattern.h`: anchor at the slot nearest the first onset (off-grid offsets kept), Auto period = slots covered by onsets rounded up to whole beats (a K-B-B-B bar repeats per bar), placing replaces the notes in the covered slots (half-slot margins). Each operation is one undo step (`LabelEditor::insert_notes`, `move_notes`, `delete_notes`); undo, redo and track loads clear the selection. Verified in the app on a scratch copy, through the saved labels file.
- **Bass tracker v0** (`src/analysis/bass_tracker.*`, SPEC 6.3 updated): kicks (click flux, broadband ratio, low rise, near a grid beat), onsets (per-bin magnitudes averaged over one period, centred difference), offsets (k x peak with window lag removed, next onset, next kick), pitch (front-end salience, central half), slides (salience changepoint, 20 ms bias), gate ratio, slot index, long notes, velocity, decay tau, confidence. Every threshold is a registry parameter (`bass.*`, `declare_bass_tracker_params`). Tracker takes the mono audio plus the front-end features and a Grid.
- Synthetic set (`tests/synthetic_set.*`, 13 cases) with exact labels: onset F 1.000 on every case, gate MAE 0.100 pooled (SPEC target 0.10 just met), pitch >= 0.90 except 28 ms notes (physics; low confidence). Full table in `docs/results/M1.md`.
- `psyight_eval` CLI and the **M1 baseline** (`docs/results/M1.md`): OculusDrift region F 0.994 (452/452 matched, 5 false positives), pitch 0.989, gate MAE 0.037, offsets -6.8 ms median. Before the grid fix it scored F 0.858: the gap was the grid offset, not tracker scatter.
- Tests: 110 doctest cases, 4183 assertions, Release.

## Known issues
- Closing the app while a track is still loading waits up to about 3 s for the analysis (make it cancellable).
- The bass roll's time axis is not pixel-aligned with the analysis plots (different y-axis label widths).
- Spectrogram display resolution at the low end is about half a bin (SPEC 6.1); CQT is an M2 option.
- Bass tracker v0 limits: gaps shorter than the 25 ms envelope window run to the next onset (a dip-depth estimate was tried and reverted: decay looks like a gap); long notes decaying below k x peak end before their gate; long notes held under a kick are split; notes under about two periods get a wrong pitch with low confidence.
